# Fine-grained incrementality

Phase 6 makes reuse an observable correctness property rather than an inferred
timing improvement. One `PL0LanguageSession` now retains independent state for
lexing, reference parsing, and semantic binding:

```text
versioned SourceEdit
        |
        v
restart-and-converge tokenizer       stable token identities
        |
        v
token-delimited parser cache         clean and recovered CST regions
        |
        v
declaration and binding cache        dependency-aware semantic reuse
```

Every cache is discarded if the edit cannot be proven to follow the cached
revision or if the grammar artifact changes.

## Reference parser

The reference LL parser memoizes block, statement, condition, expression, term,
and factor regions. A region is reusable only when its start token, every
consumed token, and the following lookahead retain their stable identities and
relative UTF-16 offsets. The relative-offset proof prevents an edit to trivia
inside a region from being mistaken for a uniform move. Relocated nodes keep
their identities and receive updated UTF-16 ranges.

Recovered regions are reusable too. Their local diagnostics, expected-token
sets, insert/delete repairs, and recovered CST are cached together. On a hit,
the parser remaps deleted tokens to the current token stream and relocates all
other evidence before replaying it. Full-parse differential tests ensure this
does not alter the observable recovery result.

## Semantic dependencies

`PL0IncrementalSemanticAnalyzer` keeps two small maps keyed by stable token ID:

* declaration signatures contain name, kind, stable scope key, lexical level,
  storage slot, and constant value;
* reference bindings contain the required semantic context, target symbol, any
  diagnostic, and a fingerprint of the declaration chain capable of binding
  that particular spelling.

A reference to `x` therefore does not depend on unrelated declarations. Adding
a nearer `x`, changing the resolved `x` kind, slot, level, or constant value,
or changing its stable scope invalidates that binding. Literal and trivia edits
reuse it. Cached bindings still materialize current source ranges and semantic
tokens, so consumers never see stale positions.

`PL0SemanticReuseMetrics` reports reused and rebuilt declarations and
references plus dependency invalidations. The Semantics workbench view displays
these counts. `PL0Analysis.experimentRun(documentURI:)` exports their sum as a
separate `semanticNodes` reuse dimension; it is never blended with token or CST
reuse.

## Correctness oracle

The Phase-6 suite applies successive edits through one incremental session and
analyzes the same resulting text through a new full frontend. It compares a
token-identity-neutral projection of symbols, scopes, references, semantic
tokens, and diagnostics, then compares generated bytecode exactly. Dedicated
tests also verify recovered-region replay against a fresh parse.

## Deliberate boundary

The reference LL and semantic passes now perform genuine fine-grained reuse.
The linked LR and Earley packages currently expose only stable-prefix adapter
evidence; ModEdit does not label that as native parser-state reuse. Genuine LR
stack checkpoints, Earley dependency invalidation, forest-node reuse, and
incremental Compiler IR require reusable-state APIs in their owning ecosystem
packages. Those algorithms should be added there and consumed by ModEdit rather
than duplicated locally.

Bytecode lowering currently reruns after a semantic change. It consumes the
incrementally validated semantic model and is checked against fresh lowering,
but it does not yet claim instruction-fragment reuse. A future shared Compiler
IR should give basic blocks stable identities and explicit dependency edges
before incremental lowering is introduced.
